01

Hướng dẫn cho người mới

Không cần biết lập trình, không cần gõ lệnh. Khoảng 15 phút, làm 3 việc: có Claude, tạo tài khoản GitHub, rồi nối GitHub vào Claude — bước cuối là bước quan trọng nhất, làm ở Phần C.

Đường ngắn nhất — đúng 3 việc bắt buộc
  1. A1 hoặc A2 — có Claude để dùng (web là đủ; app trên máy thì cần cho mục 02)
  2. B1 rồi B3 — có tài khoản GitHub và đã vào tổ chức công ty
  3. C1 — bật connector GitHub trong Claude

Mọi khối gắn nhãn Tuỳ chọn đều bỏ qua được, đọc sau lúc nào cũng được. Checklist bên phải xếp theo đúng 3 phần A · B · C này.

Phần A Có Claude để dùng

Hai đường, chọn một là đủ cho mục 01 — nối GitHub ở đường nào cũng ra kết quả y hệt vì connector gắn vào tài khoản chứ không gắn vào máy.

A1 · Nhanh nhất: dùng trên web

  1. Mở claude.ai → Sign in → đăng nhập bằng tài khoản Claude công ty cấp.
  2. Thấy khung chat là xong, không cần cài gì.
Chưa được cấp tài khoản Claude thì làm gì

Nhắn vào #oeditions xin cấp, kèm email công ty của bạn. Trong lúc chờ, bạn vẫn làm được Phần B (tài khoản GitHub) và cả mục 02 — chỉ Phần C là phải có tài khoản Claude.

Trang đang hiện hướng dẫn cho macOSWindows — chọn ở góc trên bên phải, hoặc bấm ngay đây.

A2 · App trên máy (nên cài, để dành cho mục 02)

  1. Tải bản macOS tại claude.com/download, mở file rồi kéo icon Claude vào thư mục Applications.
  2. Tải bản Windows tại claude.com/download, chạy file cài đặt, bấm Next → Install.
  3. Mở app → Sign in → trình duyệt mở ra → đăng nhập → quay lại app.
  4. Thấy khung chat và gõ được câu hỏi vào đó là xong.
Web cũng có tab Code — nhưng nó chạy ở nơi khác

Tab Code trên claude.ai/code chạy trên máy chủ ở xa, nên không cài được phần mềm lên máy bạn — giống hệt lý do tab Cowork không dùng được cho việc setup. Muốn Claude cài hộ ở mục 02 thì dùng app trên máy (hoặc gõ claude trong Terminal/PowerShell).

Phần B Tạo tài khoản GitHub

GitHub là gì? Nơi cả công ty lưu và chia sẻ code, giống Google Drive nhưng dành cho code — có lưu lịch sử ai sửa gì, lúc nào, vì sao.

B1 · Đăng ký

  1. Vào github.com/signup, đăng ký bằng email công ty.
  2. Đặt tên tài khoản dễ nhận: an-nguyen, chien-nv… Cả team nhìn thấy tên này hằng ngày.
  3. Mở hộp thư, bấm link xác nhận email.
B2 · Bật bảo mật 2 lớp (2FA) Tuỳ chọnBấm để mở

Không cần cho buổi setup hôm nay — bỏ qua vẫn tạo được tài khoản và nối được vào Claude. Bật khi bạn có 5 phút rảnh, hoặc khi GitHub tự nhắc.

  1. Vào github.com/settings/security → Enable two-factor authentication.
  2. Chọn Authenticator app → mở app xác thực trên điện thoại (Google Authenticator, Microsoft Authenticator hoặc 1Password) → quét mã QR → nhập 6 số.
Nếu bật thì lưu mã dự phòng ngay

Màn hình tiếp theo hiện một danh sách recovery codes. Cất vào trình quản lý mật khẩu hoặc in ra. Mất điện thoại mà không có mấy mã này là mất tài khoản vĩnh viễn, không ai lấy lại hộ được.

B3 · Vào tổ chức của công ty

  1. Gửi tên tài khoản GitHub vừa tạo vào #oeditions để xin vào tổ chức ownego trên GitHub.
  2. Nhận email mời → mở → Join organization.
  3. Công ty dùng đăng nhập nội bộ (SSO) thì trình duyệt hỏi thêm một bước → Authorize.

Phần C Nối GitHub vào Claude

Đây là phần quan trọng nhất của mục 01. Nối xong bạn hỏi được kiểu: "Đọc repo dự án X rồi giải thích chức năng thanh toán hoạt động thế nào" · "PR số 42 đang sửa gì?" · "Viết giúp tôi tài liệu mô tả module này cho người mới".

Nối một lần, dùng được cả app lẫn web

Connector gắn vào tài khoản Claude, không gắn vào máy. Nối ở claude.ai thì mở app Claude trên máy là đã có sẵn, và ngược lại. Không phải làm hai lần, cũng không phải cài gì thêm.

C1 · Bật connector GitHub

  1. Mở Claude — app trên máy hay claude.ai đều được, các bước y hệt nhau.
  2. Vào Settings → Connectors. Một số bản ghi menu này là Customize → Connectors; đường tắt: trong khung chat bấm + ở góc dưới bên trái → Connectors → Manage connectors.
  3. Bấm dấu + cạnh chữ Connectors để mở thư mục connector → tìm GitHub → bấm Connect.
  4. Bước dễ sai nhất — GitHub hỏi cài vào đâu. Màn hình hiện hai lựa chọn: tên tài khoản của bạn và tổ chức ownego. Chọn ownego. Chọn tên cá nhân thì về sau tick repo kiểu gì cũng không bao giờ thấy repo công ty, vì repo công ty thuộc tổ chức chứ không thuộc bạn.
    Chỗ đó ghi Request thay vì Install nghĩa là bạn không đủ quyền tự duyệt — bấm Request rồi nhắn vào #oeditions nhờ một Owner duyệt.
  5. Tiếp đó GitHub xin quyền. Chọn Only select repositories rồi tick đúng repo cần dùng → Install & Authorize.
    Chọn All repositories cũng chạy, nhưng như vậy là cho Claude thấy mọi repo bạn có quyền — kể cả repo cá nhân.
  6. Quay lại Claude. Thấy GitHub nằm trong danh sách đã kết nối là xong.

Thử ngay cho chắc: mở chat mới, gõ "Liệt kê các repo tôi có quyền truy cập trên GitHub". Nó liệt kê ra đúng danh sách bạn vừa tick là kết nối chạy thật.

Liệt kê ra mà thiếu repo riêng tư của công ty — lỗi hay gặp nhất

Tổ chức bật SSO nên phải cấp quyền thêm một lần nữa: vào github.com/settings/applications → mở mục Claude → bấm Grant ở phần Organization access. Chỗ đó ghi Request thì bấm Request rồi nhắn #oeditions.

Bật/tắt cho từng cuộc chat: bấm + ở góc dưới bên trái → Connectors → gạt công tắc GitHub.

Không thấy GitHub trong thư mục connector?

Tài khoản Team/Enterprise phải được duyệt trước: Owner vào Organization settings → Connectors → Browse connectors → chọn GitHub → Add to your team. Chưa duyệt thì thành viên không nhìn thấy. Đây không phải lỗi máy bạn — nhắn vào #oeditions.

C2 · Đính repo vào một chat hoặc một Project

Hai nút hay dùng sau đó: Sync (repo có code mới thì bấm để Claude đọc bản mới nhất) và Configure files (đổi danh sách file đã chọn).

Dùng lại nhiều lần cho cùng một dự án: tạo một Project rồi thêm repo vào Project knowledge — dấu + ở góc trên bên phải phần đó → GitHub. Từ đó mọi chat trong Project đều có sẵn code, khỏi đính lại.

  • Chọn ít file thôi — càng nhiều file càng ăn hết chỗ trống của cuộc hội thoại.

02

Cài VS Code + GitHub Desktop

Một đoạn lệnh dán vào là cài xong cả 2 app, kèm phần chứng minh vì sao đoạn lệnh đó an toàn để bạn tự kiểm tra trước khi chạy.

Hai app này để làm gì

Ngắn gọn: GitHub giữ bản gốc trên mạng, VS Code là chỗ bạn đọc và sửa trên máy mình, GitHub Desktop đưa qua đưa lại giữa hai bên.

Trên mạng GitHub Nơi cả team để chung source code. Bản gốc nằm trên server, ai cũng lấy về được, và lưu lịch sử ai sửa gì lúc nào.
Trên máy bạn VS Code Công cụ mở source đã lấy về để đọc và sửa. Cũng là nơi Claude Code chạy khi bạn nhờ nó viết hộ.
Nối hai đầu GitHub Desktop Bấm nút để đẩy phần bạn vừa sửa lên GitHub, hoặc kéo phần người khác vừa sửa về máy. Không phải gõ lệnh.

Vòng lặp hằng ngày chỉ có vậy: kéo bản mới nhất về → sửa trong VS Code → ghi lại thay đổi → đẩy lên cho cả team thấy.

Chưa được duyệt vào tổ chức GitHub của công ty thì sao

Vẫn cài và thử được hết. Lấy tạm một repo công khai bất kỳ, hoặc tự tạo một repo riêng của bạn — thao tác y hệt. Repo công ty chỉ hiện ra sau khi Team Lead duyệt; chưa thấy nó không phải do bạn cài sai.

Trang đang hiện hướng dẫn cho macOSWindows — chọn ở góc trên bên phải, hoặc bấm ngay đây.
Dán vào đâu

TerminalPowerShell hoặc tab Code của Claude. Tab Cowork không dùng được cho việc này — nó chạy trên máy chủ ở xa nên không cài phần mềm lên máy bạn được.

Dán vào Terminal

Mở Terminal: bấm Cmd + dấu cách, gõ Terminal, Enter. Copy toàn bộ khối dưới (kể cả dòng đầu bash <<'SCRIPT' và dòng cuối SCRIPT), dán vào, bấm Enter. Chạy mất 2–4 phút.

macOS · cài cả 2 app
bash <<'SCRIPT'
set -euo pipefail

# Cài Visual Studio Code + GitHub Desktop từ trang chủ của Microsoft và GitHub.
# Không dùng sudo. Không tải script lạ. Kiểm tra chữ ký số trước khi cài.
#
# Cả khối chạy trong MỘT tiến trình bash riêng (dòng `bash <<'SCRIPT'` ở trên),
# nên nếu có lỗi thì chỉ tiến trình đó dừng — cửa sổ Terminal của bạn vẫn còn,
# và bạn đọc được thông báo lỗi.

if [ "$(uname -m)" = "arm64" ]; then
  VSCODE_URL="https://update.code.visualstudio.com/latest/darwin-arm64/stable"
  GHD_URL="https://central.github.com/deployments/desktop/desktop/latest/darwin-arm64"
else
  VSCODE_URL="https://update.code.visualstudio.com/latest/darwin-universal/stable"
  GHD_URL="https://central.github.com/deployments/desktop/desktop/latest/darwin"
fi

TMP="$(mktemp -d)"
trap 'rm -rf "$TMP"' EXIT

cai_app() {
  ten="$1"; url="$2"; app="$3"; team="$4"

  if [ -d "/Applications/$app" ] || [ -d "$HOME/Applications/$app" ]; then
    echo "✅ $ten đã có sẵn trên máy, bỏ qua."
    return
  fi

  echo "==> Đang tải $ten ..."
  curl -fL --proto '=https' --tlsv1.2 -o "$TMP/app.zip" "$url"

  echo "==> Đang giải nén ..."
  mkdir -p "$TMP/out"
  # Dùng ditto (công cụ gốc của macOS), KHÔNG dùng unzip:
  # unzip làm hỏng chữ ký của app, khiến bước kiểm tra bên dưới báo lỗi oan.
  ditto -x -k "$TMP/app.zip" "$TMP/out"
  src="$(find "$TMP/out" -maxdepth 1 -name '*.app' -print -quit)"

  echo "==> Kiểm tra chữ ký số ..."
  codesign --verify --strict "$src"
  spctl --assess --type execute "$src"

  # Hai lệnh trên chỉ chứng minh "có ai đó được Apple tin cậy đã ký".
  # Dòng dưới mới ép ĐÚNG nhà phát hành — sai là dừng, không cài.
  if ! codesign -dv --verbose=2 "$src" 2>&1 | grep -q "^TeamIdentifier=$team"; then
    echo "❌ Người ký KHÔNG đúng (cần TeamIdentifier=$team). Dừng, không cài."
    exit 1
  fi

Homebrew là một công cụ cài phần mềm bằng dòng lệnh — hình dung như một cái “App Store cho Terminal”. Ai đã cài sẵn từ trước thì có cách gõ ngắn hơn, chỉ khác nhau ở chỗ đó thôi, hai cách cài ra cùng một app.

  • Hiện Homebrew 4.x.x (hoặc số nào đó) → máy đã có. Muốn gõ ngắn thì dùng dòng dưới cùng.
  • Hiện zsh: command not found: brew → máy chưa có. Hoàn toàn bình thường, đa số máy mới đều vậy. Bạn dùng đoạn lệnh dài ở trên là đủ, không phải làm gì thêm.

Vì sao đoạn lệnh trên an toàn

Bạn không cần tin ai — dưới đây là những gì tự kiểm chứng được.

1 · Không có sudo, không xin quyền quản trị

Bản Mac chép app vào /Applications, không được thì tự chuyển sang ~/Applications — thư mục riêng của bạn. Không chỗ nào đòi mật khẩu máy.

2 · Không có kiểu curl … | bash

Đây là dạng nguy hiểm nhất: tải file lạ từ mạng về chạy thẳng mà không ai đọc được nội dung. Đoạn lệnh trên chỉ tải file cài đặt của chính 2 app đó, còn toàn bộ lệnh thì bạn đang đọc bằng mắt.

3 · Chỉ tải từ tên miền chính chủ

update.code.visualstudio.com → chuyển tiếp sang vscode.download.prss.microsoft.com (CDN Microsoft) · central.github.com → desktop.githubusercontent.com (CDN GitHub). Tự kiểm tra: dán link vào trình duyệt xem nó chuyển đi đâu. Thấy tên miền khác → đừng chạy, báo team.

4 · Bắt buộc kiểm tra chữ ký số trước khi cài

Mac dùng codesign + spctl, Windows dùng Get-AuthenticodeSignature. File bị chỉnh sửa dọc đường thì bước này fail và script dừng ngay, chưa cài gì cả.

5 · Không tắt bất kỳ cơ chế bảo vệ nào

Không spctl --master-disable, không tắt Gatekeeper, không Set-ExecutionPolicy Bypass, không loại trừ thư mục khỏi Windows Defender. Ai bảo bạn làm mấy cái đó để "cài cho nhanh" — từ chối.

6 · Không chạm vào dữ liệu của bạn

Chỉ tải 2 file vào thư mục tạm, giải nén, chép 2 app, rồi tự xoá thư mục tạm. Không đọc file cá nhân, không đụng ~/.ssh, không gửi gì ra ngoài.

Đóng góp cá nhân được tính thế nào

Luật, gọn trong một câu

Mỗi thành viên phải chiếm 10%–30% của đội, xét trên cả số commit lẫn số dòng code thêm mới. Thiếu một trong hai là tính vi phạm.

Đội 6 người chia đều nhau là 16,7%/người — nằm giữa khoảng, rất an toàn. Không cần chia chính xác, chỉ cần đừng có ai quá ít hoặc quá nhiều.

Hai con số đó tính ra sao

Công thức
% commit của bạn = số commit bạn là tác giả / tổng commit của repo
% dòng của bạn   = số dòng bạn THÊM vào       / tổng dòng cả đội thêm vào

Máy đọc git log của nhánh chính. Dòng bị xoá không tính, chỉ tính dòng thêm.

Không tính dòng của file máy tự sinh — nên đừng lo npm install làm lệch tỉ lệ, và cũng đừng trông chờ nó làm đẹp tỉ lệ của bạn:

package-lock.json, yarn.lock, pnpm-lock.yaml, go.sum, Cargo.lock, Gemfile.lock, thư mục dist/, build/, out/, vendor/, node_modules/, coverage/, generated/, .next/, .nuxt/, file *.min.js, *.min.css, *.map, *.snap, và file nhị phân (ảnh, font, zip…).

Sáu việc nên làm

  1. Ai làm phần nào thì tự commit phần đó. Đừng để một người gom code cả đội rồi commit hộ — người đó vọt lên trên 30%, những người kia rơi xuống dưới 10%.
  2. Khai báo git đúng và thống nhất trên mọi máy. Kiểm tra git config user.name và git config user.email. Cùng một người mà mỗi máy một email sẽ bị đếm thành hai tác giả — cả hai đều dưới sàn. Lỡ rồi thì thêm file .mailmap ở gốc repo (Lê An <email-chinh> <email-cu>) là gộp lại được.
  3. Đừng để một người dựng toàn bộ scaffold. create-next-app, code sinh sẵn, file cấu hình copy về — chúng vẫn được tính là dòng của người commit. Ai dựng khung thì nên bớt phần việc code sau đó, hoặc chia khung cho vài người.
  4. Người làm thiết kế / tài liệu / demo / PM vẫn phải có commit. Git không nhìn thấy Figma, slide hay video. Hãy đưa sản phẩm của mình vào repo: file .md tài liệu, ghi chú thiết kế, kịch bản demo, script test… Đó là commit thật và tính vào tỉ lệ.
  5. Pair programming thì luân phiên người commit. Dòng Co-authored-by được ghi nhận là bằng chứng cộng tác, nhưng không chia lại phần trăm — 100% thuộc về người đứng tên commit.
  6. Người chỉ đi merge sẽ trượt. Commit merge được đếm là commit nhưng thêm 0 dòng, nên % commit lên còn % dòng vẫn 0. Người đó cần có commit code thật.

Tự kiểm tra xem có phạm quy không

Đứng ở nhánh chính trong repo của đội (git checkout main), dán cả khối vào Terminal/PowerShell. Kết quả ra đúng như cách BTC tính, và tự chấm DAT hay !! cho từng người:

Tự kiểm tra · chạy trong repo của đội
git log --numstat --format='@%aN' | awk -F'\t' '
/^@/ { a = substr($0, 2); c[a]++; tc++; next }
NF == 3 && $1 ~ /^[0-9]+$/ {
  f = $3
  # File đổi tên được git ghi rút gọn — lấy lại tên MỚI rồi mới lọc
  if (f ~ / => /) {
    if (f ~ /\{/) { sub(/\{[^}]* => /, "", f); sub(/\}/, "", f) }
    else { sub(/^.* => /, "", f) }
  }
  if (f ~ /(^|\/)(dist|build|out|vendor|node_modules|coverage|generated|\.next|\.nuxt)\//) next
  if (f ~ /(package-lock\.json|yarn\.lock|pnpm-lock\.yaml|go\.sum|Cargo\.lock|Gemfile\.lock)$/) next
  if (f ~ /\.(lock|min\.js|min\.css|map|snap)$/) next
  l[a] += $1; tl += $1
}
END {
  printf "%-24s %8s %8s   %s\n", "THANH VIEN", "COMMIT", "DONG", "KET QUA"
  for (a in c) {
    pc = 100*c[a]/tc; pl = tl ? 100*l[a]/tl : 0
    if (pc >= 10 && pc <= 30 && pl >= 10 && pl <= 30) k = "DAT"
    else if (pc < 10 && pl < 10)                      k = "!! THIEU ca hai"
    else if (pc > 30 || pl > 30)                      k = "!! VUOT 30%"
    else                                              k = "!! LECH mot chi so"
    printf "%-24s %7.1f%% %7.1f%%   %s\n", a, pc, pl, k
  }
}' | (read h; echo "$h"; sort)
Đọc kết quả
  • DAT — cả hai chỉ số nằm trong 10–30%, không sao.
  • !! THIEU ca hai — dưới sàn cả commit lẫn dòng, cần nhận thêm việc.
  • !! VUOT 30% — ôm quá nhiều, nên nhường phần việc cho người khác.
  • !! LECH mot chi so — hay gặp nhất là nhiều commit nhưng 0% dòng: dấu hiệu chỉ đi merge.
  • Không hiện tên trong bảng = chưa có commit nào. Đây là ca nặng nhất.

Chạy lại sau mỗi chặng, ai lệch thì còn kịp cân lại phần việc ở chặng sau.

Vài điều cần biết

  • Squash merge xoá dấu vết. Nếu đội gộp mọi PR thành một commit của một người, cả đội sẽ hiện ra như một người làm. Giữ lịch sử commit thật.
  • Đừng chẻ nhỏ commit để lấy số. Giám khảo đọc cả tiêu đề commit và nội dung thay đổi; commit rỗng hoặc sửa khoảng trắng để đủ chỉ tiêu là phản tác dụng.
  • Kết quả là số học, không phải AI phán đoán. Máy tính một lần rồi đưa cùng con số đó cho cả hai giám khảo; giám khảo không tính lại. Đội thấy sai số thì báo BTC kèm lệnh git log để đối chiếu.
  • Đội quá ít người thì ngưỡng này không áp được — 3 người thì tối đa 3 × 30% = 90%, không thể đủ 100%. Trường hợp đó BTC xử lý riêng, không trừ điểm đội.
